# Production Tasks implementation status

`lib/api/tasks.ts` dispatches the existing task UI's routes using the verified context's Supabase user client. It provides bounded task pages (maximum 200), filters, counts, detail, create, versioned edits, comments, subtasks, archive, founder delete/restore and notifications. List DTOs omit long descriptions; detail supplies them. Detail bounds are latest 200 comments, first 200 subtasks and latest 50 audit events. Additional history navigation and subtask pagination must be provided before claiming unbounded histories.

`202611240002_tasks.sql` adds request idempotency, task numbers, comment/subtask tables, in-app notifications, indexes, write RPCs and daily Paris-time due/overdue reminder generation. Create retries serialize per actor/workspace/key. All direct writes are revoked; user-JWT RLS and RPC field authorization are enforced. Comment attribution is server-trusted. Parent completion checks serialize with subtask changes, and unfinished subtasks require an explicit parent-completion decision. Founder deletion is reversible and retains history.

`nam_process_reminders(w uuid)` requires a live Founder session with any elected MFA satisfied, or a verified service-role call and is scoped to one workspace. A protected scheduler must invoke it; its existence does not establish that scheduling or email delivery is configured. Reminder inserts deduplicate by task/recipient/Paris day. Notification reads re-check current task access.

Current policies remain conservative: section eligibility and task ownership; only founder has team-wide task access. Sales/production manager templates do not silently grant all team records. Real project briefs and explicit participants now exist through migration 016; they never broaden task visibility. Broader manager scopes remain separate policy work. Do not infer access to a parent record from a task assignment.

`supabase/tests/tasks.sql` supplies 16 behavioral pgTAP assertions with disposable Auth identities; that SQL test runner has not been executed. `test/tasks-db.test.mjs` does execute the actual foundation and task migrations in PGlite PostgreSQL with Supabase auth-function fixtures and real authenticated role switches. Its workflow passes assignment, retries, conflict, cross-workspace denial, freelancer denial, comment attribution, subtasks, stale updates, forbidden reassignment/direct writes/self-promotion, search pagination, counts, MFA restriction, delete/restore, reminder deduplication, notification reads and suspension. This is PostgreSQL execution evidence, not a hosted Supabase/Auth/PostgREST or browser test. Full launch verification additionally needs live API behavior, cross-task IDs, malicious input, real concurrency and deployed browser flows.

Validation on 24 November 2026: TypeScript `--noEmit` passed, and the domain PostgreSQL workflow test passed. Re-run from this directory with `node --test test/tasks-db.test.mjs` after installing the locked development dependencies.

Migration `009_task_dates` enforces the technical YYYY-MM-DD serialization range (AD year 1 through 9999, or no deadline) in PostgreSQL itself. Direct RPC attempts to store infinity, negative infinity, BC dates or five-digit years are rejected; failed updates retain the existing date/version. This is a format boundary, not an invented business scheduling window.

Migration `011_task_query_scopes` computes trusted active membership/session/MFA scopes once per SQL statement for task RLS. Assigned task pages add an explicit owner predicate and an appropriate composite index. The existing direct-permission regression tests pass with this migration; the separate performance benchmark must determine measured load results. It preserves membership/session revocation, section eligibility and task ownership. Migration 015 establishes optional elected MFA for every role, including Founder.

The root API router owns session verification, origin/CSRF checks and error responses. Do not expose this dispatcher without those checks. Supabase errors are mapped to safe public messages; no secrets, database details or client data belong in logs.

Current daily attention/time/project filters are in migrations 017/019. The initial browser page renders 50 summaries and retains bounded API pagination. Native eight-user and 10,000-task evidence is in [REINVENTION_VALIDATION.md](docs/REINVENTION_VALIDATION.md).
